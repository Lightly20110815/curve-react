# 曲線時報 v4 首轮评审（修改前）

当前版未通过。三位代理分别检查 Anthropic 相似度、AI 模板感、艺术指导与必交付要求，先读文件，再看浏览器截图；没有给数字评分。

对象：[修改前的留档](preview-before-revision.html)。桌面 1440 × 1000，手机 390 × 844，浅色和深色均通过页面里的主题选择器切换。后续修改及复审见[第二轮记录](revision-report.md)。

| 审稿方向 | 判定 | 理由 |
| --- | --- | --- |
| Anthropic / Claude 相似度 | 专项通过 | 冷灰底、粗黑中文无衬线、硬边分栏占主导，未发现典型奶油底、暖衬线、陶土橙的站点组合。专辑封面的橙色属于真实内容。这一判定不代表原创性或工艺通过。 |
| AI 模板感与工艺 | 失败 | 大字号先占位、内容后填入；手机按模块堆叠；长页只处理了首屏两栏的关系。 |
| 艺术指导与必交付要求 | 失败 | 标题断词、手机阅读次序失衡；下落动画尚未承担内容表达。单一概念比 v3 清楚，但未达到可发布的完成度。 |

1. **中文标题没有经过排版。** 桌面和手机都把“用户名”拆成“用 / 房名”。`max-width:11ch` 与 `overflow-wrap:anywhere` 配合大字号，允许任意断行；文章块又用 `min-height:490px` 撑出大块空底。修正应从这篇文章的语义断行和内容高度开始。[桌面证据](screenshots/desktop-light.png)、[手机证据](screenshots/mobile-light.png)。

2. **手机把文章推到了首屏底部。** 站名、说明、播放器、曲库和四条次导航先出现。实际测得首篇标题顶部在约 782px；844px 高的第一屏没有显示完整标题。音乐一等公民不能只靠多占面积来实现。保留紧凑播放控制，曲库和次导航应让出首篇入口。[手机证据](screenshots/mobile-light.png)。

3. **长页的侧栏没有收尾。** 曲库与导航结束后，右栏仍留下大片空白，竖线一直延续到页底；播放控制也没有随阅读保留。文章目录和曲库目前只是首屏并排，“带声轨的文集目录”没有进一步落实成阅读关系。应处理播放控制的持续可用性，以及侧栏结束之后的版面。[完整桌面证据](screenshots/desktop-light-full.png)。

4. **PV 要求仍未满足。** 当前报头是 720ms 错开入场，换曲时歌名是 480ms 滑入。这两种动作保留了下落外形，尚未与文章表达或音乐节奏建立关系。不能靠再加一个装置补救，应集中完成一个有明确内容理由的文字动作。[开场录屏](opening-motion.webm)。

专项中还发现 hero 使用 `#ec534b/#f88b81`，与其他位置的强调红不同；没有内容理由支撑第二套红色，宜统一。但改色本身无法解决上面四项。

实际浏览器里，13 篇文章与日期正常显示，手机没有页面横向溢出，真实文章照片和首张专辑封面加载成功。[深色桌面](screenshots/desktop-dark.png)、[浅色手机全页](screenshots/mobile-light-full.png)、[深色手机全页](screenshots/mobile-dark-full.png)也已留档。这里只验证了深浅模式的静态画面，没有完成四时段的视觉验收或 Windows / Android 字体实机检查。

音乐另外实测了播放、下一首和暂停。`A Little Love`、`As It Was` 均进入实际播放，播放时间递增、没有媒体错误，切换前后只有一个 audio 元素。这是独立 HTML 的结果，尚未验证与 RootLayout 的集成，不能称为已经接入全局控制器。

三份意见一致认为：下一轮应先处理真实内容的排版与阅读次序，不能用更多装饰填空。上述修改完成、重新截图复审之前，不应宣称“没有 AI 味”。
